Protocol Family Grouping¶

A protocol family is a base class named after the family plus its member classes. What each class returns from id() is what the selectors on Protocol match against. The rulings were set on #2441, #2443, #2446, #2462 and #2517.

The id() Criterion¶

A family base lists its direct concrete subclasses. An abstract intermediate is left out, and so is everything beneath it. #2441.

The member list takes either of these forms:

  • Members only. IP.id() is ('IPv4', 'IPv6'); AH and ESP are not in it, since they belong to the separate abstract IPsec, whose id() is ('AH', 'ESP'). HTTP.id() is ('HTTP/1', 'HTTP/2').

  • The base’s own name, then the members. VLAN.id() is ('VLAN', 'C_Tag', 'S_Tag') and L2TP.id() is ('L2TP', 'L2TPv2').

ARP.id() is ('ARP',) alone; see Member Shapes.

Abstract Family Names¶

An abstract family name composes its members. The ruling on #2462 is that IPv6_Ext lists its direct concrete members in its id(), and that each member narrows its own id() to itself.

Grouping by Name¶

Members share a base because they share a name, not a wire format. HTTP/1 and HTTP/2 share HTTP, IPv4 and IPv6 share IP, and AH and ESP share IPsec. #2441.

IP and IPsec define no read(). The HTTP class does, but yields no instance of itself (below).

Dispatching Bases¶

A versioned family’s base dispatches on both paths (#2524). Parsing octets through it, constructing it from fields and its from_data give the member the octets, fields or data model describe, never an instance of the base. In HTTP, _dispatch_version() picks the member from the octets, for a payload a transport port binds to HTTP as well, and _dispatch_fields() from the fields. The other versioned families are tracked on #2574.

Octets neither version takes, a frameless HTTP/2 connection preface among them, are Raw with no error on the transport path, and a direct HTTP(...) on them raises ProtocolError (#2524). Octets the dispatcher gives HTTPv2 that its parser then refuses, such as a preface and three octets, are Raw with the parser’s error.

Nothing dispatches to InARP ('InARP',): under EtherType 0x0806, operation 8 parses as ARP with alias InARP. Only RARP ('RARP', 'DRARP') is bound to EtherType 0x8035 (Reverse_Address_Resolution_Protocol). A parsed RARP takes DRARP as its alias for operation 5, and DRARP ('DRARP',) inherits the __index__ of RARP.

A family-inclusive member is selected by any sibling’s registry key (a key of pcapkit.protocols.__proto__), because each expands to the shared family name (below). A narrow member is selected by its own name and by the key of each family whose id() lists it: AH and ESP by IPsec and by IPv6_Ext, HTTPv1 and HTTPv2 by HTTP.

Chained Records¶

TLS and SSLv2 records sharing a TCP segment are chained layers, not a list on one layer (#2517, #2567): each record dissected after the first is the previous record’s payload, so a TLS record’s dynamic alias names its own version – a ServerHello then a ChangeCipherSpec read TCP:TLS 1.3:TLS 1.2 – and an SSLv2 CLIENT-HELLO then a CLIENT-MASTER-KEY read TCP:SSLv2:SSLv2. DTLS does not chain: two DTLS records in one datagram read DTLS 1.2:Raw (#2535).

Canonical Names¶

A versioned protocol’s display name includes its version. This is the stated preference on #2444, not a settled rule. L2TPv2’s name is Layer 2 Tunnelling Protocol version 2. The HTTP/1.1 and HTTP/2 classes define no name of their own, so they report Hypertext Transfer Protocol, which carries no version.

ICMPv4 is the case where the RFC’s own name carries no version. The ruling on #2446: ICMPv4 keeps its versioned class and module name, but its id() drops the version for the RFC canonical name (RFC 792 names it plain ICMP), and its name carries no “version 4”. ICMPv6 keeps its own version, since RFC 4443 names it with one.

IGMPv1 follows the same shape, by the same reasoning (#2439, #2506). RFC 1112 names IGMPv1’s protocol plain IGMP, so IGMPv1.id() is ('IGMP',) and its alias is 'IGMP', while IGMPv2.id() and IGMPv3.id() keep their own versions, ('IGMPv2',) and ('IGMPv3',), since RFC 2236 and RFC 3376 name them with one. The family base’s id() follows: IGMP.id() is ('IGMP', 'IGMPv2', 'IGMPv3'), the family-inclusive shape, because IGMPv1’s canonical name and the family’s own name are the same string – the same shape ICMP.id() takes, ('ICMP', 'ICMPv6').

HTTP takes the RFC names as well (#2524). RFC 9113 names its protocol HTTP/2, so HTTPv2.id() is ('HTTP/2',). RFC 9112 names HTTP/1.1, but the HTTP/1 class also reads messages declaring 1.0 or 0.9, so HTTPv1.id() is the major version, ('HTTP/1',), and alias carries the exact one. No member’s name is the family’s, so HTTP.id() lists the members alone, ('HTTP/1', 'HTTP/2'), the shape of IP.id().

Selector Matching¶

A family name selects every version, and each version name selects its own. #2443. On an IPv4 frame, 'IP' in is True and 'IPv6' in is False. On an IPv6 frame, 'IP' in is True and 'IPv4' in is False.

HTTP follows it too (#2524). On an HTTP/1.1 frame, 'HTTP' in and 'HTTP/1' in are True and 'HTTP/2' in is False, since the layer is HTTPv1; an HTTP/2 frame is the reverse.

What a selector on a frame or a layer reaches is defined by expand_comp(), __contains__(), __getitem__() and Protocol.__eq__. Selectors are case-insensitive: 'ipv4' in an IPv4 frame is True.

  • String == compares against the class and its own id() only; the selector is not expanded. On a parsed IPv4 layer, ipv4 == 'IPv4' is True and ipv4 == 'IP' is False. On a parsed C-Tag layer, == 'VLAN' is True, since VLAN is in its id(), and == 'S_Tag' is False, though 'S_Tag' in the layer is True. On a parsed HTTP/1.1 layer, == 'HTTP/1' is True and == 'HTTP' is False, since no member’s id() carries HTTP, though 'HTTP' in the layer is True.

  • in and [] expand the selector first. A registry key becomes its class plus that class’s id(), as does a class object, and a layer matches when any of those appears among its own class and id(). So 'S_Tag' in a C-Tag frame is True: S_Tag expands to S_Tag and VLAN, and the C-Tag layer’s id() carries VLAN.

  • A string that is not a registry key is matched by name alone against each layer’s class and id(), so an alias such as 'HTTP/1.1' selects no layer: 'HTTP/1.1' in frame is False.

ProtoChain matches more widely: its index(), count() and in also compare each layer’s alias, so 'HTTP/1.1' in frame.protochain is True.

No Invented Suffixes¶

The family base takes the family’s own name. IP, IPsec, HTTP, VLAN and L2TP are the precedent. No _Family suffix is added (#2446).

A protocol class takes its module’s name, whatever its canonical name and id(). The family base takes the family’s name and a member its module’s versioned name: igmpv1 holds IGMPv1, though its id() is ('IGMP',) (above). A module holds one protocol class. protocol is exempt: its ProtocolBase and Protocol are framework bases rather than dissectors. Both ruled on #2529.

The name match ignores case and underscores: c_tag holds C_Tag and linux_sll1 holds LinuxSLL1. The schema/ and data/ modules follow the same layout: the top-level class takes the module’s name, and sub-structure classes such as Query share its module. Ruled on #2529, where the classes that do not match yet are pending: arp.InARP, tls.SSLv3 and null.NoPayload.
