=========================================================
PyPCAPKit - Comprehensive Network Packet Analysis Library
=========================================================

PyPCAPKit is an open source Python library for
`PCAP <https://en.wikipedia.org/wiki/Pcap>`__ file extraction, construction and
analysis.

.. important::

   The whole project requires **Python 3.8** or later. CI supports 3.11 to 3.15, and
   still tests the end-of-life 3.8 to 3.10 without letting a failure block anything.

About
=====

:mod:`PyPCAPKit <pcapkit>` is an independent open source library, with
:mod:`DictDumper <dictdumper>` as its formatted output dumper. Compared with
:mod:`Scapy <scapy>`, `DPKT`_ and `PyShark`_, it gives more detailed packet
information through a more *Pythonic* interface.

.. deprecated:: 0.8.0

   |jspcapy|_, a command line tool for PCAP extraction built on :mod:`pcapkit`,
   has been merged into :mod:`PyPCAPKit <pcapkit>` as its CLI.

----------------
Module Structure
----------------

.. list-table::
   :header-rows: 1

   * - Subpackage
     - Holds
   * - Interface (:mod:`pcapkit.interface`)
     - the user-facing functions
   * - Foundation (:mod:`pcapkit.foundation`)
     - extraction, reassembly, flow tracing and the registries behind them
   * - Protocols (:mod:`pcapkit.protocols`)
     - every protocol family
   * - Utilities (:mod:`pcapkit.utilities`)
     - the cross-cutting services the library is built with
   * - CoreKit (:mod:`pcapkit.corekit`)
     - the core data structures, such as
       :class:`~pcapkit.corekit.infoclass.Info` and
       :class:`~pcapkit.corekit.protochain.ProtoChain`
   * - ToolKit (:mod:`pcapkit.toolkit`)
     - the per-engine adapters behind reassembly and flow tracing
   * - DumpKit (:mod:`pcapkit.dumpkit`)
     - the output dumpers added to those of :mod:`DictDumper <dictdumper>`
   * - Constants (:mod:`pcapkit.const`)
     - the constant enumerations, generated by :mod:`pcapkit.vendor`
   * - Vendor (:mod:`pcapkit.vendor`)
     - the crawlers that regenerate :mod:`pcapkit.const` from the upstream
       registries

-----------------
Engine Comparison
-----------------

Besides its own parser, :mod:`pcapkit` can extract through `Scapy`_, `DPKT`_,
`PyShark`_, `PyPCAP`_, `pcap-ct`_ and `PyPCAPFile`_: every one of them but
`PyShark`_ is faster, and every one supports less. :doc:`engines` compares their
support, Python versions, prerequisites and per-packet speed.

Installation
============

.. note::

   The sources use 3.8 syntax and nothing converts them, since the ``bpc-*``
   backport tools are unmaintained (:issue:`2051`), so ``requires-python`` is
   ``>=3.8`` and pip refuses an older interpreter. 3.8 to 3.10 are end-of-life
   and best-effort, and individual *engines* stop earlier than the library
   does; see :ref:`engine-prerequisites`.

Install the current version from PyPI:

.. code-block:: shell

   pip install pypcapkit

Or the latest version from the repository:

.. code-block:: shell

   git clone https://github.com/JarryShaw/PyPCAPKit.git
   cd PyPCAPKit
   pip install -e .
   # and to update at any time
   git pull

For local development, ``make setup`` installs the :file:`Pipfile` through
``pipenv`` with the virtualenv and package caches inside the project directory,
and points ``lxml`` at Homebrew's ``libxml2``/``libxslt`` where they are
installed. That avoids ``pipenv`` cache permission errors under
:file:`~/Library/Caches` and ``lxml`` builds missing those headers:

.. code-block:: shell

   make setup

To run ``pipenv`` directly, use the same cache layout and skip any stale,
user-local :file:`Pipfile.lock`:

.. code-block:: shell

   PIPENV_VENV_IN_PROJECT=1 \
   PIPENV_CACHE_DIR=$PWD/.pipenv-cache \
   PIP_CACHE_DIR=$PWD/.pip-cache \
   pipenv install --skip-lock --dev

The optional engines and addons install as extras:

.. code-block:: shell

   # for DPKT only
   pip install pypcapkit[DPKT]
   # for Scapy only
   pip install pypcapkit[Scapy]
   # for PyShark only
   pip install pypcapkit[PyShark]
   # for PyPCAPFile only
   pip install pypcapkit[PyPCAPFile]
   # for PyPCAP only -- builds from source, see below
   pip install pypcapkit[PyPCAP]
   # for pcap-ct only -- pure Python, works on 3.12+; never alongside PyPCAP
   pip install pypcapkit[PCAP_CT]
   # for ESP payload decryption
   pip install pypcapkit[crypto]
   # every core addon -- CLI display, ESP decryption and NGAP decoding;
   # no engine above is included
   pip install pypcapkit[all]
   # or explicitly
   pip install pypcapkit emoji cryptography pycrate

.. important::

   ``all`` leaves out ``pypcap`` and ``pcap-ct`` on purpose. ``pypcap`` compiles a
   C extension, which would demand a compiler and the `libpcap`_ development
   files from everyone installing ``pypcapkit[all]``; everything else in ``all``
   installs from a wheel. ``pcap-ct`` needs no compiler, but it and its
   ``libpcap`` dependency are published only as **pre-releases** (1.3.0b3 and
   1.11.0b29), and ``all`` should not install a beta nobody asked for. Install
   either through its own extra, as above.

.. versionchanged:: 1.5.0

   ``all`` installs the core addons only: ``emoji``, ``cryptography`` and
   ``pycrate``. The engines and vendor-crawler dependencies it carried in 1.4
   -- ``dpkt``, ``scapy``, ``pyshark``, ``requests`` and ``beautifulsoup4`` --
   moved to the ``dev`` extra, alongside ``pypcapfile`` (:issue:`910`).

.. warning::

   **Install only one of** ``pypcap`` **and** ``pcap-ct``. Both own the top-level
   |pcap|_ module, and ``pip`` installs both without complaint. ``pcap-ct`` then
   wins the import and shadows ``pypcap``'s extension module, so
   ``engine='pypcap'`` stops working -- measured on Python 3.10. :mod:`pcapkit`
   warns with an :class:`~pcapkit.utilities.warnings.EngineWarning` naming both
   distributions and the winner, but cannot undo it.

Some engines need more than a ``pip install`` -- a :program:`tshark` binary, a C
compiler and the `libpcap`_ headers, or an older interpreter.
:ref:`engine-prerequisites` gives each constraint and its reason.

The CLI needs the ``cli`` extra:

.. code-block:: shell

   pip install pypcapkit[cli]
   # or explicitly
   pip install pypcapkit emoji
