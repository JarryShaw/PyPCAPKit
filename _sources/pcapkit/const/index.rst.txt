Constant Enumerations
=====================

.. module:: pcapkit.const

The constant enumerations of :mod:`pcapkit`, generated by :mod:`pcapkit.vendor`.

.. _unrecognised-values:

Unrecognised Values
-------------------

Nearly every :term:`registry` below departs from :mod:`enum` in one deliberate way:
looking up a value it does not define does **not** raise. Its ``_missing_`` override
returns a member-like object named for the unassigned or reserved band the value
falls in. Only a value no band covers, or of the wrong type, raises
:exc:`ValueError`.

That object is usually **not** installed: the registry does not grow, and a repeat
lookup returns an equal but distinct object. The exceptions, of which
:ref:`mint-criterion` gives the full split:

* :class:`~pcapkit.const.mh.cga_type.CGAType` installs a permanent member, so
  ``__members__`` and iteration grow.
* :class:`~pcapkit.const.tcp.flags.Flags`,
  :class:`~pcapkit.const.ftp.command.CommandType` and the Mobility Header and
  radiotap flag registries, such as
  :class:`~pcapkit.const.mh.binding_ack_flag.BindingACKFlag`, hand back to
  |aenum|_'s flag base, which caches the composed object in the value lookup
  table only: a repeat lookup returns the same object, while ``__members__``
  and iteration are unchanged.
* :class:`~pcapkit.const.hip.transport.Transport`,
  :class:`~pcapkit.const.ieee802_11.type.Type`,
  :class:`~pcapkit.const.ieee802_11.management_subtype.ManagementSubtype`,
  :class:`~pcapkit.const.ipv6.extension_header.ExtensionHeader`,
  :class:`~pcapkit.const.pcapng.tls_key_label.TLSKeyLabel` and the memberless
  :class:`~pcapkit.const.reg.apptype.apptype.AppType` base raise
  :exc:`ValueError` for any unknown value.

This lets the enumerations decode live captures, where a code assigned after this
release was generated is routine, so iterating a registry need not list every value
it resolves. Since whether a repeat lookup returns the same object varies by registry,
compare unassigned members by value, not identity.

The template in :mod:`pcapkit.vendor.default` emits the override's common form; the
valid range and band names come from each registry's source data, so the individual
overrides are not documented per class.

   :doc:`../foundation/registry` covers the other half of extending a registry:
   once a code exists, registering a parser class, schema or engine against it.
