ICMPv6 - Internet Control Message Protocol for IPv6¶

pcapkit.protocols.internet.icmpv6 contains ICMPv6 only, which implements extractor for Internet Control Message Protocol for IPv6 (ICMPv6) [*], whose structure is described as below:

Bits

Name

Description

0

Type

1

8

icmpv6.code

Code

2

16

icmpv6.checksum

Checksum

4

32

class pcapkit.protocols.internet.icmpv6.ICMPv6(file=None, length=None, **kwargs)[source]¶

Bases: ICMP[ICMPv6, ICMPv6]

This class implements Internet Control Message Protocol for IPv6.

This class parses the following ICMPv6 message types, which are registered in the self.__type__ attribute:

Type

Data Parser

Data Constructor

Destination Unreachable

_read_data_type_destination_unreachable()

_make_data_type_destination_unreachable()

Packet Too Big

_read_data_type_packet_too_big()

_make_data_type_packet_too_big()

Time Exceeded

_read_data_type_time_exceeded()

_make_data_type_time_exceeded()

Parameter Problem

_read_data_type_parameter_problem()

_make_data_type_parameter_problem()

Echo Request / Echo Reply

_read_data_type_echo()

_make_data_type_echo()

Any other type, including Neighbor Discovery (RFC 4861) and Multicast Listener Discovery (RFC 9777), is kept as its raw message body, see _read_data_type_none() and _make_data_type_none().

Changed in version 1.6.0: The checksum is computed when make() is given none, over the pseudo it is given or by the enclosing IPv6 layer, and verified by that layer under CHECKSUM_VERIFY (#2470).

class pcapkit.protocols.data.internet.icmpv6.ICMPv6(*args, **kwargs)[source]¶

Bases: Protocol

Data model for ICMPv6 protocol.

The fields below are the only ones every ICMPv6 message shares (RFC 4443); what follows them is read entirely differently depending on type, which is why each message kind below adds its own fields rather than this base class growing a union of them all.

type: Type¶

ICMPv6 type.

code: int¶

ICMPv6 code. Left untyped as a bare int here because its meaning is entirely type-dependent; each subclass below documents which registry (if any) its own code values are drawn from.

checksum: bytes¶

Checksum.

length: int¶

Message length, in octets, header included. ICMPv6 messages carry no length field of their own – this is simply how many octets ICMPv6.read was handed, kept here so the whole message can be told apart from a truncated capture.

checksum_status: ChecksumStatus¶

Outcome of verifying checksum, present only when the enclosing IPv6 layer verified it under CHECKSUM_VERIFY.
