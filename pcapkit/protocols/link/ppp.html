PPP - Point-to-Point Protocol¶

pcapkit.protocols.link.ppp.protocol contains PPP, which implements the extractor for the Point-to-Point Protocol (PPP) [*] frame of RFC 1661, in the HDLC-like framing of RFC 1662, whose structure is:

Octets

Bits

Name

Description

0

0

ppp.address

Address (0xFF, optional)

1

8

ppp.control

Control (0x03, optional)

2

16

ppp.protocol

Protocol (one octet when compressed)

The Address and Control fields are read where the frame opens with 0xFF 0x03, and the Protocol field is one octet where its first octet is odd. LCP, IPCP, IPv6CP, PAP and CHAP packets are read at header level, as ppp.control_packet.

Added in version 1.7.0.

class pcapkit.protocols.link.ppp.protocol.PPP(file=None, length=None, **kwargs)[source]¶

Bases: Link[PPP, PPP]

This class implements Point-to-Point Protocol.

The frame is dispatched from Frame.__proto__ and PCAPNG.__proto__ at LINKTYPE_PPP and LINKTYPE_PPP_HDLC, from Link.__proto__ at EtherType 0x880B, and as the payload of a PPPoE session and an L2TPv2 data message.

The Address and Control fields are read where the frame opens with 0xFF 0x03, and the Protocol field is one octet where its first octet is odd, as Address-and-Control-Field-Compression and Protocol-Field-Compression leave them (RFC 1661 Section 6). Under LINKTYPE_PPP_HDLC a frame not opening with 0xFF 0x03 is Cisco HDLC (RFC 1547 Section 4.3.1), which is refused.

A protocol number the ControlPacket registry holds a layout for – LCP, IPCP, IPv6CP, PAP and CHAP – is read as a control packet at header level, its Code, Identifier and Length, and the rest of the frame is the next layer as Raw. Any other protocol number dispatches the next layer, through the protocols registered in the self.__proto__ attribute:

Index

Protocol

Internet_Protocol_version_4

pcapkit.protocols.internet.ipv4.protocol.IPv4

Internet_Protocol_version_6

pcapkit.protocols.internet.ipv6.protocol.IPv6

Added in version 1.7.0.

Defaults

__proto__: DefaultDict[int | Protocol, ModuleDescriptor[ProtocolBase] | Type[ProtocolBase]]¶

Protocol index mapping for decoding next layer, see self._decode_next_layer & self._import_next_layer. Keyed by PPP protocol number rather than by EtherType, so this class keeps a registry of its own instead of sharing Link.__proto__; an entry is registered with register_ppp().

__control__: DefaultDict[Protocol | int, str | tuple[Callable[[Protocol, ControlPacket], ControlPacket], Callable[[Protocol, ControlPacket | Mapping[str, Any]], ControlPacket]]]¶

Protocol number to control packet method mapping, see read() and make(). A str value names the methods _read_control_${name} and _make_control_${name}, any other value is a (parser, constructor) pair; either works on the layout the ControlPacket registry holds for the protocol number, and one with no layout there is carried as the next layer instead. An entry is registered with register_control() and register_ppp_control().

read(length=None, *, alias=None, **kwargs)[source]¶

Read Point-to-Point Protocol.

Structure of PPP frame [RFC 1661][RFC 1662]:

+----------+----------+----------+-------------+---------+
|   Flag   | Address  | Control  |  Protocol   | Padding |
| 01111110 | 11111111 | 00000011 | 8/16 bits   |    *    |
+----------+----------+----------+-------------+---------+

The Flag sequence and the Frame Check Sequence are not captured.

Parameters:

  • length (int | None) – Length of packet data.

  • alias (int | None) – Code the frame was dispatched under, as Frame and PCAPNG pass the link type.

  • **kwargs (Any) – Arbitrary keyword arguments.

Return type:

PPP

Returns:

Parsed packet data.

Raises:

ProtocolError – If the frame does not open with the Address and Control fields under LINKTYPE_PPP_HDLC, or a control packet’s Length is below its fixed fields.

Make (construct) packet data.

Parameters:

  • pfc (bool) – Whether the Protocol field is one octet, under Protocol-Field-Compression.

  • control_packet (ControlPacket | Mapping[str, Any] | None) – Control packet, given as its code, identifier and data and optionally its length, for a protocol number the ControlPacket registry holds a layout for.

  • payload (bytes | ProtocolBase | Schema) – Payload data.

Return type:

PPP

Returns:

Constructed packet data.

Raises:

ProtocolError – If protocol is a name, or does not fit its field; if its first octet is odd in two octets, or even in one, since the frame would read back with the other width; if control_packet is missing for a protocol number with a layout, or given for one without; if a field of it does not fit; or if, with acfc, the frame would open with 0xFF 0x03.

classmethod register(code, protocol)[source]¶

Register a new protocol class for a PPP protocol number.

Notes

The fully qualified class name of the new protocol class should be {protocol.module}.{protocol.name}.

Parameters:

  • code (Protocol) – PPP protocol number

  • protocol (ModuleDescriptor[ProtocolBase] | Type[ProtocolBase]) – module descriptor or a ProtocolBase subclass

Important

This overrides Link.register because self.__proto__ is keyed by PPP protocol number rather than by EtherType (#2511).

Raises:

pcapkit.utilities.exceptions.RegistryError – If protocol is not a class, or not a ProtocolBase subclass.

Warns:

pcapkit.utilities.warnings.RegistryWarning – If this protocol number is already registered and the incumbent differs from the replacement; the message names both. See Protocol.register for the guard, and for the shipped descriptor a restore puts back (#1504).

classmethod register_control(code, meth)[source]¶

Register a control packet parser.

Parameters:

  • code (Protocol) – PPP protocol number.

  • meth (str | tuple[Callable[[Protocol, ControlPacket], ControlPacket], Callable[[Protocol, ControlPacket | Mapping[str, Any]], ControlPacket]]) – Method name, or a (parser, constructor) pair of callables, to parse and construct its control packets; see __control__.

Warns:

RegistryWarning – If a different entry is already registered for code; it is overwritten. Handing back the entry already stored, or one equal to it, is a silent no-op, so an override can be undone.
