IEEE 802.11 - Wireless LAN MAC Header¶

pcapkit.protocols.link.ieee802_11 contains IEEE802_11 only, which implements the extractor for the IEEE 802.11 MAC header [*] of a protocol version 0 frame, as a LINKTYPE_IEEE802_11 capture carries it or Radiotap hands it on. Its fields, in the order they appear, numeric ones little-endian:

Name

Octets

Present

frame_control

2

always (§9.2.4.1)

duration_id

2

always (§9.2.4.2)

addr1

6

always (§9.2.4.3)

addr2

6

Management, Data, and Control frames that carry a TA (§9.2.4.3, §9.3.1)

addr3

6

Management and Data frames (§9.2.4.3)

seq_ctrl

2

Management and Data frames (§9.2.4.4)

addr4

6

Data frames with To DS and From DS set (§9.2.4.3)

qos_control

2

QoS Data subtypes (§9.2.4.5)

ht_control

4

QoS Data subtypes and Management frames with +HTC/Order set (§9.2.4.6)

layout() gives the rule per frame type. A Control frame of a subtype whose layout this class does not model, and an Extension frame, are read as the minimal frame format of §9.2.3: the first three fields only. A Control Frame Extension frame and an S1G Beacon lay out B8-B15 of Frame Control differently; see FrameControl.

Scope¶

  • The frame body (§9.2.4.7) is kept as Raw, protected or not.

  • The FCS (§9.2.4.8), where one was captured, stays at the end of the body: this class does not decide whether a capture carries one, which behind radiotap is a Flags bit Radiotap decodes but does not pass on.

  • Pad octets that radiotap’s data-pad flag says follow the header stay at the start of the body, for the same reason.

  • A protocol version other than 0 is refused: version 1 is the PV1 frame format of §9.8, whose Frame Control field is laid out differently, and versions 2 and 3 are reserved.

pcapkit.protocols.schema.link.ieee802_11.layout(frame_control)[source]¶

Decide which fields a protocol version 0 MAC header carries.

  • A Management frame carries Address 2, Address 3 and Sequence Control whatever its subtype, and HT Control when +HTC/Order is set (IEEE Std 802.11-2020 §9.3.3, Management frames; §9.2.4.1.10, +HTC/Order subfield).

  • A Data frame carries the same three, Address 4 when To DS and From DS are both set, QoS Control when the QoS bit (B7) of its subtype is set, and HT Control when that bit and +HTC/Order are both set (§9.3.2, Data frames).

  • A Control frame carries Address 2 for the subtypes in CONTROL_WITH_ADDR2, and Address 1 alone for CTS and Ack (§9.3.1, Control frames).

  • Every other frame – a reserved Control subtype, a Control Wrapper, whose octets after Address 1 are Carried Frame Control and HT Control, and every Extension frame – is read as the minimal frame format that §9.2.3, General frame format, makes present in every frame, reserved types and subtypes included: Frame Control, Duration/ID and Address 1. What follows stays in the frame body.

This departs from the Linux kernel’s ieee80211_hdrlen() deliberately: a Control Wrapper and the reserved Control subtypes 0 and 1 read 10 octets where it gives 16, and an Extension frame reads 10 where it gives 4.

Parameters:

frame_control (int) – Frame Control field, as the little-endian integer read off the wire.

Return type:

Layout

Returns:

The fields present after Address 1.

pcapkit.protocols.schema.link.ieee802_11.CONTROL_WITH_ADDR2¶

Control frame subtypes whose MAC header carries a TA (or BSSID) as Address 2 after the RA; IEEE Std 802.11-2020 §9.3.1, Control frames, and IEEE Std 802.11ax-2021 for Trigger. CTS and Ack carry the RA alone. A Control Frame Extension frame takes the six octets after the RA as Address 2, as the Linux kernel’s ieee80211_hdrlen() reads it; in a DMG DTS (extension 6) they are NAV-SA rather than a TA, and NAV-DA stays in the body.

class pcapkit.protocols.data.link.ieee802_11.QoSControl(tid, eosp, ack_policy, amsdu_present, bits_8_15)[source]¶

Bases: Data

Data model for the QoS Control field (IEEE Std 802.11-2020 §9.2.4.5).

Only the subfields every QoS Data subtype places alike are decoded. What bits 8-15 carry depends on the subtype and on the kind of station that sent the frame, which the MAC header does not say, so they are kept whole as bits_8_15.

tid: int¶

TID (bits 0-3).

eosp: bool¶

EOSP (bit 4). In a frame a non-AP station sends, the same bit says whether bits_8_15 is TXOP Duration Requested or Queue Size.

ack_policy: int¶

Ack Policy Indicator (bits 5-6).

amsdu_present: bool¶

A-MSDU Present (bit 7); reserved in the subtypes that carry no data.

bits_8_15: int¶

Bits 8-15, which are TXOP Limit, TXOP Duration Requested, Queue Size, AP PS Buffer State, or the mesh subfields, by subtype and sender.

class pcapkit.protocols.data.link.ieee802_11.HTControl(variant, value)[source]¶

Bases: Data

Data model for the HT Control field (IEEE Std 802.11-2020 §9.2.4.6).

Its first bits name the variant the rest of the field takes; the variants’ own subfields are not decoded.

variant: Literal['HT', 'VHT', 'HE']¶

The variant, 'HT' when bit 0 is clear, 'VHT' when bit 0 is set and bit 1 clear, and 'HE' when both are set (IEEE Std 802.11ax-2021).

value: int¶

The whole field, as the little-endian integer read off the wire.
