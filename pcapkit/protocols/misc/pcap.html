PCAP File Headers¶

pcapkit.protocols.misc.pcap contains header descriptions for PCAP files, including global header (Header) and frame header (Frame).

Global Header¶

pcapkit.protocols.misc.pcap.header contains Header only, which implements an extractor for global headers [*] of PCAP, whose structure is described as below:

typedef struct pcap_hdr_s {
    guint32 magic_number;   /* magic number */
    guint16 version_major;  /* major version number */
    guint16 version_minor;  /* minor version number */
    gint32  thiszone;       /* GMT to local correction */
    guint32 sigfigs;        /* accuracy of timestamps */
    guint32 snaplen;        /* max length of captured packets, in octets */
    guint32 network;        /* data link type */
} pcap_hdr_t;

Changed in version 1.5.0: A global header cut short rebuilds as captured, where it rebuilt at full width (#1470).

Header Schemas¶

pcapkit.protocols.schema.misc.pcap.header.GLOBAL_HEADER_LEN = 24¶

Length of the PCAP global header, which opens the file. The one home of this value (#1739); the format fixes it, so it is never configurable.

Added in version 1.5.0.

pcapkit.protocols.schema.misc.pcap.header.MAGIC_NUMBER: Dict[bytes, tuple[Literal['big', 'little'], bool]]¶

PCAP magic numbers, as the octets open the file, mapped to the byte order ('big' or 'little') and the timestamp resolution (True for nanoseconds, False for microseconds) each one declares. The one home of these values (#1739); the format fixes them, so they are never configurable.

Added in version 1.5.0.

pcapkit.protocols.schema.misc.pcap.header.RESOLUTION: Dict[bool, int]¶

Units per second of a record’s ts_usec field, keyed by the nanosecond flag its file’s magic number declares (MAGIC_NUMBER): microseconds, or nanoseconds. The one home of these values (#1739); the format fixes them, so they are never configurable.

Added in version 1.5.0.

pcapkit.protocols.schema.misc.pcap.header.RESOLUTION_PLACES: Dict[bool, int]¶

Decimal places of a ts_usec fraction at each resolution of RESOLUTION, keyed the same way – six for microseconds, nine for nanoseconds – and derived from it, so that an epoch rounded to its file’s resolution follows the one home (#1739).

Added in version 1.5.0.

Frame Header¶

pcapkit.protocols.misc.pcap.frame contains Frame only, which implements an extractor for frame headers [†] of PCAP, whose structure is described as below:

typedef struct pcaprec_hdr_s {
    guint32 ts_sec;     /* timestamp seconds */
    guint32 ts_usec;    /* timestamp microseconds */
    guint32 incl_len;   /* number of octets of packet saved in file */
    guint32 orig_len;   /* actual length of packet */
} pcaprec_hdr_t;

Changed in version 1.5.0: bytes(frame) and packet hold this frame’s own octets, where they held the next frame’s (#357), and the parsed time is timezone-aware UTC. The parsed len is the on-wire length and cap_len the captured one, where the two were swapped (#618).

Link type a frame’s data is dispatched under.

Parameters:

int | None

Returns:

For LinkType.RAW data whose first octet carries IP version 4 or 6, LinkType.IPV4 or LinkType.IPV6; otherwise proto.

Note

LINKTYPE_RAW (101) carries a bare IPv4 or IPv6 datagram, and only the version nibble of its first octet tells which, so it has no entry of its own in __proto__ (#1502). Dispatched as IPV4 or IPV6, it reaches whatever those link types are registered against. An entry registered under RAW itself is used as it stands, and data of any other version is kept as Raw. Number of octets of packet data actually captured and saved in the file, i.e. the record header’s incl_len, and so the number of octets packet holds. Named after Wireshark’s frame.cap_len, registered as “Frame length stored into the capture file”.
