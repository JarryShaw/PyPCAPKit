DNS - Domain Name System¶

pcapkit.protocols.application.dns.protocol contains DNS only, which implements an extractor for Domain Name System (DNS) messages [RFC 1035], whose header is:

Octets

Bits

Name

Description

0

0

dns.length

Message Length (over TCP only)

0

0

dns.id

Identifier

2

16

dns.flags

QR, Opcode, AA, TC, RD, RA, Z, AD, CD, RCODE

4

32

dns.qdcount

Question Count

6

48

dns.ancount

Answer Count

8

64

dns.nscount

Authority Count

10

80

dns.arcount

Additional Count

Over TCP, the two-octet length precedes the message, so every offset above moves two octets on (RFC 1035 Section 4.2.2, RFC 7766 Section 8).

How a parse reads a message:

        flowchart TD
    IN["octets at port 53"] --> GIVEN{"framed= given?"}
    GIVEN -->|yes| READ["read as it says"]
    GIVEN -->|no| WHOLE{"a whole message that fits<br/>behind a length field?"}
    WHOLE -->|no| UNFRAMED["one message, unframed"]
    WHOLE -->|yes| PLAIN{"do the sections the header<br/>counts fit the octets?"}
    PLAIN -->|no| FRAMED["one message, framed"]
    PLAIN -->|yes| EXACT{"does the framed one end<br/>exactly at its length?"}
    EXACT -->|no| UNFRAMED
    EXACT -->|yes| END{"does the plain one stop<br/>short of the end?"}
    END -->|yes| FRAMED
    END -->|no| TIE{"a question in the framed one only,<br/>or a further exact framed message?"}
    TIE -->|yes| FRAMED
    TIE -->|no| UNFRAMED
    FRAMED --> NEXT{"a whole framed message after it?"}
    NEXT -->|yes| CHAIN["a further DNS layer"]
    NEXT -->|no| REST["the rest as Raw"]

Added in version 1.7.0.


class pcapkit.protocols.application.dns.protocol.DNS(file, length=None, /, *, framed=None, layer=None, protocol=None, context=None)[source]¶

Bases: Application[DNS, DNS]

This class implements Domain Name System.

Overloads:

  • file (IO[bytes] | bytes), length (int | None) = ..., /, *, framed (bool | None) = ..., layer (str | None) = ..., protocol (str | ProtocolBase | Type[ProtocolBase] | None) = ..., context (ContextRegistry | ProtocolContext | Mapping[str, ProtocolContext] | Iterable[ProtocolContext] | None) = ...

  • *, framed (bool | None) = ..., context (ContextRegistry | ProtocolContext | Mapping[str, ProtocolContext] | Iterable[ProtocolContext] | None) = ..., **fields (Any)

A message is parsed whole: the header, the four sections, the RDATA of the types __rdata__ registers and the options of the OPT pseudo-record of EDNS(0) (RFC 6891) that __option__ registers. Each domain name records the compression it was read with (Name), so a message rebuilds as captured.

Over TCP the two-octet length precedes the message, which framed=True reads and writes. A parse not given framed reads the length where a whole message decodes behind it and the octets read worse as a plain message, as _frames_message() weighs them, much as TLS tries SSLv2 on what its own parser refuses (The SSL Family): the port the transport dispatches on is the same for TCP and UDP. A further whole message after a framed one is dissected as another DNS layer, the previous one’s payload, as TLS records are; a message the segment ends inside is not reassembled and stays Raw.

Any other type, and RDATA its decoder cannot read exactly, is kept as raw octets. The EDNS(0) options decoded are edns-client-subnet (ClientSubnet), COOKIE (Cookie), edns-tcp-keepalive (TCPKeepalive) and Extended DNS Error (ExtendedError); any other is kept as raw octets.

make(*, id=0, qr=False, opcode=Opcode.Query, aa=False, tc=False, rd=False, ra=False, z=0, ad=False, cd=False, rcode=RCode.NoError, question=(), answer=(), authority=(), additional=(), framed=False, message_length=None, compress=False, trailer=b'', payload=b'', **kwargs)[source]¶

Make (construct) packet data.

The section counts are those of the entries given. A question entry is a mapping of name, type and class, as Question is. A record is a mapping of name, type, class, ttl, rdlength and rdata, as ResourceRecord is, or, for the OPT pseudo-record, of the fields of OPT. rdata is raw octets, or a mapping of the fields of the type’s data model, as __rdata__ registers it. A name is a Name, which writes the compression it records, its labels, or its presentation form.

  • qr (bool) – Whether the message is a response.

  • opcode (Opcode | int) – Kind of query.

  • aa (bool) – Authoritative answer.

  • z (int) – Reserved bit.

pcapkit.protocols.application.dns.protocol._frames_message(octets)[source]¶

Whether octets are a message behind the TCP length field.

Parameters:

octets (bytes) – Octets of a DNS layer, with framed not given.

Return type:

bool

Returns:

Whether a whole message behind a length field opens octets and decodes, and octets do not decode as a message, or decode no better. Where both readings decode and the framed message ends exactly at its length, the framed one is taken if the plain one stops short of the end of octets; if it reads to the end, the framed one is taken where it counts a question and the plain one none, or where a further framed message follows that ends exactly at its length too. So a plain message whose ID equals the octets after it, with its question, stays plain.

Note

A length read as an ID makes the flags read as the question count, which flags of zero leave at zero, so the plain reading of a framed message with such flags can decode: it stops short of the end, or reads an octet run it lands on, such as a following message’s length, as an RDLENGTH counting the rest.

Over TCP, the message length the prefix gives less the header; else the rest of the data. Packing, where __length__ is unset, the body as given.
