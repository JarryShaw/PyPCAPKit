STP - Spanning Tree Protocol¶

pcapkit.protocols.application.stp.protocol holds STP, the abstract base of the Spanning Tree Protocol family [*], whose Bridge Protocol Data Units (BPDUs) are told apart by their Protocol Version Identifier. Each version is a member of its own:

Version

Class

Specification

BPDUs

0

STPv0

IEEE Std 802.1D-2004 clause 9

Configuration, 35 octets, and Topology Change Notification (TCN), 4 octets

2

RSTP

IEEE Std 802.1Q-2022 clause 14

RST, 36 octets

3

MSTP

IEEE Std 802.1Q-2022 clause 14

MST, 102 octets and an MSTI Configuration Message of 16 for each MSTI

The members share the first four octets alone, the Protocol Identifier, the Protocol Version Identifier and the BPDU Type, so the base parses no BPDU. LLC address 0x42 is the family’s, as DSAP and SSAP both, so LLC.__proto__ binds this base, paired, and it picks the member as IEEE Std 802.1Q-2022 clause 14.4 validates a BPDU, by _classify(). A BPDU that clause discards is left Raw behind LLC, and a direct parse of it raises ProtocolError; so is an SPT BPDU, of version 4, which the family does not dissect.

The bridge’s control plane computes the active topology rather than relaying frames, so the family is a user of the stack, as a routing protocol is (Protocol Layer Placement). The proprietary per-VLAN variants, which no public specification defines, are not dissected.

Added in version 1.9.0.

class pcapkit.protocols.application.stp.protocol.STP[_PT: Data, _ST: Schema](file, length=None, /, *, version=None, layer=None, protocol=None, context=None)[source]¶

Bases: Application[_PT, _ST], Generic[_PT, _ST]

This class implements all protocols in the Spanning Tree Protocol family.

  • Spanning Tree Protocol (STPv0) [IEEE Std 802.1D-2004]

  • Rapid Spanning Tree Protocol (RSTP) [IEEE Std 802.1Q-2022]

  • Multiple Spanning Tree Protocol (MSTP) [IEEE Std 802.1Q-2022]

It is abstract, as OSPF is, and dispatches on both paths, never giving an instance of this class (#2574). The version keyword names the member, and make() does not take it; without it, octets give the member _classify() picks, and fields are refused. The Protocol Version Identifier alone does not pick it: a Configuration BPDU is one whatever its version, and an MST BPDU that fails its checks is an RST BPDU, so from_data() reads the data model’s class, as LinuxSLL.from_data does. See __new__().

Note

The subpackage does not track the dispatch tier. STP is dispatched from LLC.__proto__ at Bridge_Spanning_Tree_Protocol, since LLC is what carries it.

classmethod _classify(data)[source]¶

Validate a received BPDU as IEEE Std 802.1Q-2022 clause 14.4 does.

With a Protocol Identifier of zero, a BPDU Type of 0x00 and 35 octets or more is a Configuration BPDU, and one of 0x80 and 4 octets or more a TCN BPDU, whatever the version; with a BPDU Type of 0x02, a version of 2 and 36 octets or more is an RST BPDU. A version of 3 or more, with 35 octets or more, is an RST BPDU where _is_mst() fails; where it holds, version 3 is an MST BPDU, and a later version the SPT BPDU of Shortest Path Bridging, version 4, which extends it and which no member reads. Anything else is discarded.

Parameters:

data (bytes) – The BPDU, its octets alone.

Return type:

Literal[-1, 0, 2, 3]

Returns:

0, 2 or 3, the version of the member that reads it, or -1 for a BPDU the clause discards or no member reads.
