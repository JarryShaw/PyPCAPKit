1.9.0 – 2026-11-28¶

Documentation of this release

1.9.0 decodes Neighbor Discovery in ICMPv6, adds dissectors for IEEE 802.2 LLC and SNAP and for the Spanning Tree Protocol family LLC carries, reassembles SCTP user messages and TLS records split across TCP segments, and verifies HIP’s HMAC and signature parameters given the keys. Its breaking changes, each marked a breaking change to and ending with how to migrate, are to where pcapkit.corekit’s multi-word modules and DNS’s name codec live, to the Mobility Header’s option payloads, which parse as protocols rather than stay octets, and to the conda package, which no longer bundles the optional dependencies.

pcapkit.corekit¶

Changed¶

  • a breaking change to the names of the pcapkit.corekit modules that follow, whose words an underscore now separates, ruled in review of #3142 (#2934), with the list taken on #3153 (#3172): pcapkit.corekit.schema.shortread is pcapkit.corekit.schema.short_read, pcapkit.corekit.schema.extlen is pcapkit.corekit.schema.ext_len, pcapkit.corekit.const.ipheader is pcapkit.corekit.const.ip_header and pcapkit.corekit.const.tcpheader is pcapkit.corekit.const.tcp_header. A common joined name, as pcapkit.corekit.schema.byteorder, keeps its form. The old paths raise ImportError, with no alias. To migrate, import from the new path, as from pcapkit.corekit.schema.short_read import hoist_short_read.

  • a breaking change to where DNS’s name codec lives, now that ICMPv6’s DNS Search List option reads names too (#2934, #3142). read_name, make_name, name_to_text and text_to_labels move from pcapkit.protocols.application.dns.schema to the new pcapkit.corekit.schema.domain_name, and POINTER_LIMIT from pcapkit.protocols.application.dns.const to pcapkit.corekit.const.domain_name.POINTER_LIMIT, with no re-export, so the old paths raise ImportError. DNS reads and writes names as before. To migrate, from pcapkit.protocols.application.dns.schema import read_name becomes from pcapkit.corekit.schema.domain_name import read_name.

pcapkit.foundation¶

Added¶

  • SCTP user-message reassembly, 'sctp' in an extraction’s reassembly, by SCTP, which pcapkit.foundation.reassembly exports as SCTP_Reassembly, under the PCAP and PCAP-NG engines (#2935, #3137). It joins a message’s DATA chunks, a run of consecutive TSNs from the B bit to the E bit on one stream (RFC 9260 Section 6.9), or its I-DATA chunks by message ID, in FSN order (RFC 8260). A buffer is keyed by the ports and verification tag, so the fragments sent on any path of a multi-homed association join, and of a TSN or FSN received twice the first copy is kept; there is no timeout unless one is given. The messages are ReassemblyData.sctp, each one’s packet its user data dispatched on its PPID by SCTP.analyze, as the new sctp_message() parses it. An incomplete message is reported as its received runs under strict=True and as its octets up to the first hole otherwise.

  • TLS record reassembly, 'tls' in an extraction’s reassembly, by TLS, which pcapkit.foundation.reassembly exports as TLS_Reassembly, under the PCAP, PCAP-NG, DPKT, Scapy and PyPCAPFile engines (#2938, #3138), so a record split across TCP segments, which no segment’s TLS layer can parse, is parsed whole. Each direction of a connection on a port TCP binds to TLS is one octet stream in sequence order, from its SYN or a segment opening a record header to its FIN or RST, a segment ahead of the octets held waiting for them and the first copy of octets received twice kept. The new TLS.record_header cuts it into records, and every record is reported, as ReassemblyData.tls, one a single segment holds included, since a boundary is known only from the record before it. A complete record’s packet is the record parsed by the new TLS.analyze_record, as tls_record() parses it, and an incomplete one’s is None, as DTLS reassembly leaves it. TCP reassembly’s sequence-number arithmetic moves to the new pcapkit.utilities.seqnum.unwrap(), which both read.

pcapkit.protocols¶

Added¶

  • Neighbor Discovery (RFC 4861) in ICMPv6: types 133 to 137 decode into RouterSolicitation, RouterAdvertisement, NeighborSolicitation, NeighborAdvertisement and Redirect, where 1.8.x kept their bodies as octets, with the flags IANA’s registries assign and a router preference as the new RouterPreference (RFC 4191), and rebuild byte-exact, whole or cut (#2934, #3142). Their options decode through the new ICMPv6.__option__: those of RFC 4861 Section 4.6, Route Information (RFC 4191), RDNSS and DNSSL (RFC 8106), RA Flags Extension (RFC 5175), Captive-Portal (RFC 8910), PREF64 (RFC 8781), Advertisement Interval and Home Agent Information (RFC 6275), and Nonce (RFC 3971). Any other option keeps its octets as UnknownOption, and a Length of zero, or one the option’s layout does not fill, raises ProtocolError. register_icmpv6_option() registers a parser for a further option. The option types are the new NDOption, crawled from IANA; it and RouterPreference are exported as ICMPv6_NDOption and ICMPv6_RouterPreference.

  • LLC (IEEE Std 802.2) and SNAP (RFC 1042), dissectors for Logical Link Control and the Subnetwork Access Protocol (#2936, #3143). An Ethernet frame whose Length/Type field is a length, up to 0x05DC, the body of an IEEE 802.11 data frame carrying an MSDU, and a PCAP or PCAP-NG frame of LINKTYPE_ATM_RFC1483, whose payloads 1.8.x kept as Raw, dispatch to LLC; a protected, A-MSDU, reserved or no-data 802.11 body stays Raw. LLC reads the DSAP, the SSAP with its C/R bit and the I, S or U control field, and hands an I or UI PDU’s information field on by its DSAP through LLC.__proto__; a DSAP LLC.__paired__ flags, as SNAP’s and STP’s are, is handed on only when the SSAP, less its C/R bit, is the same. register_lsap() registers a protocol for a further DSAP, its paired setting the flag. SNAP hands its payload on by its protocol identifier as an EtherType under the OUI 00-00-00 (RFC 9542 Section 3), and keeps it Raw under any other. Ethernet keeps the octets past a length, its pad among them, as trailer, and its make() takes trailer and refuses a length or trailer it would not read back. The SAPs and the S and U functions are pcapkit.const.llc, generated by pcapkit.vendor.llc and exported as LLC_LSAP, LLC_SupervisoryFunction and LLC_ModifierFunction.

  • STP, the abstract base of a versioned family, and its members STPv0 (IEEE Std 802.1D-2004), RSTP and MSTP (IEEE Std 802.1Q-2022), dissectors for the Spanning Tree Protocol’s BPDUs, carried by an LLC PDU whose DSAP and SSAP are both 0x42 (#3115, #3156). A parse gives STPv0 for a Configuration or Topology Change Notification BPDU whatever its version, MSTP for a version 3 BPDU that passes MST’s length checks, and RSTP for an RST BPDU or a later-version one those checks reject; any other BPDU, Shortest Path Bridging’s SPT BPDU included, is kept as Raw with the reason as its error. version 0, 2 or 3 names the member on a parse or a build, and protocol_version keeps the octet as captured. The protocol versions, BPDU types and port roles are pcapkit.const.stp, generated by pcapkit.vendor.stp and exported as STP_ProtocolVersion, STP_BPDUType and STP_PortRole.

  • verification of HIP’s HIP_MAC, HIP_MAC_2, HIP_SIGNATURE and HIP_SIGNATURE_2 parameters, over the scope RFC 7401 Section 6.4 gives (#2939, #3140). Given a HIPContext as context, HIP records each outcome, a HIPAuthStatus, as the parameter’s hmac_status or signature_status, warning with a ProtocolWarning on one that fails or whose key cannot be applied; a parse with no context records nothing, and a parse and a rebuild are otherwise unchanged. The context holds HIPAssociation instances, an association’s HIP-gl and HIP-lg integrity keys, given or derived by HIPAssociation.from_keymat (RFC 7401 Section 6.5), for the HMACs, which need only the standard library; and HIPIdentity instances, a host’s HIT and parsed HOST_ID, for the RSA, DSA, ECDSA and EdDSA signatures, which need the crypto extra. ECDSA_LOW, pre-hashed EdDSA and HIP version 1 are reported as UNSUPPORTED. An association’s keys stay out of its __repr__() and of the data model, so no dump carries them.

Changed¶

  • a breaking change to the Mobility Header’s option payloads that belong to other protocols, which MH parses as the protocol class its new registries hold, where 1.8.x kept their octets (#2937, #3136). The selector of TrafficSelectorSuboption and QoSTrafficSelectorAttribute is parsed as MH.__selector__ holds for its ts_format (RFC 6088). The data of options 54, 60 and 61 and the context of options 56 and 57, the multicast options of RFC 7028, RFC 7161 and RFC 7411, are parsed as MH.__multicast__ holds for the option and the octet naming the payload’s format. Each field holds a ProtocolBase, a Raw where no dissector is registered, as every key is by default, and a dump nests it. MH.register_selector, MH.register_multicast, register_mh_selector() and register_mh_multicast() register a dissector, refusing TS format 0 and a pair the RFCs do not define. A parse given one warns with a ProtocolWarning and keeps the payload Raw, its reason as the error. The makers take bytes or a parsed protocol. To migrate, read the octets one level down, as option.selector.data where it was option.selector, and likewise option.data.data for options 54, 60 and 61 and option.context.data for options 56 and 57.

pcapkit.vendor¶

Changed¶

  • Vendor.split_references writes a registry’s citation of a dated IEEE standard, such as IEEE Std 802.1Q-2014, as the documentation’s new ieee role, which links the standard’s IEEE SA page as the rfc role links an RFC; an undated one, such as IEEE Std 802.3, stays text (#3168, #3173). The generated enumerations’ docstrings cite them that way, as do the docstrings and pages citing a dated IEEE standard.

Project infrastructure¶

Changed¶

  • a breaking change to the conda package: a release is published to Anaconda as one noarch: python package, carrying the core functionality alone, where each release had a package per platform and Python that vendored every optional dependency, and outgrew the storage quota, so 1.8.1’s uploads failed (#3133, #3145). It takes aenum, chardet and typing_extensions from conda-forge and vendors dictdumper and tbtrim, so it no longer carries the cryptography, emoji and pycrate that 1.8.1’s bundled. Without them an encrypted ESP payload is not decrypted, a HIP signature is reported as UNSUPPORTED, NGAP is kept as Raw, and the command line prints plain text. To migrate, install them from pip in the environment, as pip install pycrate cryptography emoji.

  • every build of the documentation, on GitHub Pages and on Read the Docs, names its version in the sidebar and opens the same page in stable, latest (develop) or its own release on Read the Docs, and the changelog’s index and each entry link that release’s documentation, unless Read the Docs holds no build of it (#3134, #3144, #3139, #3155). The documentation’s front page has a table of the versions, which the README links.

  • the docs extra pins sphinx-autodoc-typehints 3.17.7, where 1.8.1 pinned 3.17.6 (#3169).

Fixed¶

  • GitHub Pages’ 404.html sent a path under a release Read the Docs holds no build of to Read the Docs’ own 404 page. versions.json leaves those releases out, so such a path gets the plain not-found page (#3135, #3141).
